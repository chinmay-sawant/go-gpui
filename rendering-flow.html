Every frame in the window

Replayable page

internal/window/draw.go:10-14 · internal/replay/replay.go:14

replay.Draw walks display.Order and issues Ebiten draw calls directly on the screen:

  • OpFillRect: vector.FillRect, or a path with FillPath for rounded corners (fill.go, fill_round.go)
  • OpLine: one filled rectangle built from PaintLineGeometry (line.go)
  • OpText / OpBullet: Ebiten text/v2 from op.Font.Bytes(), baseline placed by face ascent, glyphs cached in Ebiten's atlas (text.go, text_cache.go)
  • OpGridRun: its border segments in order (grid.go)
↓

Fallback page

internal/window/draw.go:16-41

The Ebiten texture built from Page.Image() is blitted every frame, scaled until a new layout arrives. This is the old path, now only for pages the replay cannot draw. While a fallback page is on screen, the window paints a small bitmap fallback badge in the top-right corner so the active mode is visible.

Bytes, PNG, PDF: what is still used

ThingIn the login windowWhere it still runs
Full-page raster image.Image No. layout.Lay never runs for this page. Fallback pages, and on demand inside Page.PNG().
PNG bytes No. The desktop window never encodes a frame. -web mode serves GET /frame.png (internal/web/page_http.go:42); tests read PNG() (internal/page/page_image.go:29-47).
PDF No, never. Nothing in ownframe calls any PDF writer.
Font bytes Yes, once per face. op.Font.Bytes() parses into a GoTextFaceSource, cached in text_cache.go. Glyph masks live in Ebiten's atlas.
Small bitmaps Glyph masks and GPU geometry. Normal Ebiten drawing, not a page-sized buffer.

Scrolling

The wheel offset is passed to replay.Draw; content size comes from Display.Width/Height, so no bitmap is needed to clamp it.

Engine side: the operation list comes from gowkhtmltopdf/layout.DisplayList, which shares its placement with Lay and adds Display.Boxes for hit testing.
