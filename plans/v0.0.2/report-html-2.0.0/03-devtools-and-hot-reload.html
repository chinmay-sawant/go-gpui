DevTools and hot reload

The window draws an inspector over the page, and it polls a file on disk for edits. Neither path changes the page picture.

DevTools: F12 or Ctrl+Shift+I opens an overlay with box outlines, operation colours, and frame stats.
The overlay is window chrome. It never calls Redraw, and a test holds the page PNG to the byte.
GET /debug/state serves the same numbers as JSON in web mode.
Hot reload polls Config.File and Config.ThemeFile every 250 ms. A bad parse keeps the last good picture.
The diagram traces one reload, and the table lists what the swap keeps and clears.

DevTools

Press F12 or Ctrl+Shift+I to toggle an overlay that the page owns. The window type-asserts host.Inspector on the screen it already holds (internal/window/devtools.go:40). A screen without the interface gets no overlay and no compile change (documentation/devtools.md:86).

type Inspector interface {
    DevTools() bool
    SetDevTools(on bool)
    Stats() Stats
}

Config.DevTools starts the overlay on (internal/page/page.go:54). Page.SetDevTools and Page.DevTools read and change the flag at runtime (internal/page/page_devtools.go:10). The window follows the flag once per frame in devSync (internal/window/devtools.go:48). A browser that keeps F12 for itself or a phone without a keyboard uses that switch (documentation/devtools.md:17).

The toggle keys belong to the window. devOwns claims F12, Ctrl+Shift+I, and o while the overlay is on (internal/window/devtools_own.go:6). devtoolsKeys runs before the page key handling, and devKeyStep swallows the press and the release (internal/window/devtools_keys.go:22). The page handler never sees either one (documentation/keys.md:56).

The overlay draws last. Draw fills the background, draws the content, then the scrollbars and the context menu, then drawDevTools when the flag is on (internal/window/draw.go:22).

Hovering outlines the innermost box under the cursor in red #e5484d. A click pins a box in blue #1a56db (internal/window/devtools_paint.go:14). Each outline has a label in the shape tag#id WxH (internal/window/devtools_paint.go:46). The panel sits at the bottom left, above the horizontal scrollbar strip, and sizes itself from the widest line (internal/window/devtools_panel_geom.go:5, internal/window/devtools_draw.go:33).

Ops mode outlines every operation in paint order. drawDevOps walks display.Order and colours each outline by kind (internal/window/devtools_ops.go:23). Fills are blue, strokes red, lines orange #d97706, text green #176b45, images violet #7c3aed, grid runs cyan #0891b2 (internal/window/devtools_ops.go:12). Noop and unknown operations paint nothing and get no outline. A text operation carries its baseline in Y, so the outline uses the line box from op.InkDescent - op.H (internal/window/devtools_counts.go:67).

The stats panel prints ten lines, plus one for a hovered box and one for a pinned box (internal/window/devtools_stats.go:26).

The overlay never touches the page

The overlay is window chrome, the way the scrollbar thumbs and the fallback badge are (documentation/devtools.md:3). No path in internal/window calls Redraw to show it, and drawDevTools only reads shell state (internal/window/devtools_draw.go:15).

TestDevToolsLeavesPageAlone renders one page with the overlay off and on and compares the results (internal/window/devtools_page_test.go:16). It asserts equal Page.PNG bytes (:73), equal Page.Generation (:69), and equal operation and box counts (:77). The test turns ops mode on and sets a hovered and a pinned box first, so the strongest path is the one under test.

While the overlay is on, the pointer belongs to the overlay. pointer() calls devPointer before s.app.Hover (internal/window/pointer.go:22). devHover records the innermost box under the cursor from Boxes() without calling the page (internal/window/devtools_hover.go:5). The page picture stays still, so the pixels the stats describe do not change (documentation/pointer.md:29).

A click pins the box under the cursor. A click on the same box or anywhere on the panel clears the pin (internal/window/devtools_pick.go:57, :42). Alt+click forwards Press and Click to the page, and the release follows the forwarded press (internal/window/devtools_pick.go:57, :31).

A devtools key does not type its letter. devtoolsKeys swallows the key until it goes up, and a swallowed key also drops the printable input of the frame, so o toggles the operation view without typing (internal/window/devtools_keys.go:18). pageKeyStep reports false for a press and a release the overlay ate, so the page watch never sees them (internal/window/devtools_own.go:58).

Closing the overlay clears the hovered and pinned boxes and sends one hover for the current cursor, so a stale :hover does not stick (internal/window/devtools_life.go:42). A new generation drops a pick whose id is gone from Boxes() (internal/window/devtools_life.go:23).

Suppressing pointer input freezes the page's hover and press state at its last value. A pinned :hover looks odd, and the alternative is a cascade redraw per mouse move (documentation/devtools.md:110, plans/v0.0.2/devtools.md:245).

GET /debug/state

Serve registers the route next to the others (internal/web/server.go:51). The handler takes the server mutex, so it never reads the page mid-redraw (internal/web/debug_http.go:27, internal/web/server.go:29).

The JSON body holds width, height, generation, fallback, boxes, stats, and per-kind operation counts (internal/web/debug_http.go:14). fallback is true when the page has no display list and has an image (internal/web/debug_http.go:33). stats appears when the screen implements host.Inspector (internal/web/debug_http.go:47). ops appears when a display list exists, and it counts fill, stroke, line, text, bullet, image, and grid runs, plus a total (internal/web/debug_ops.go:5). Noop, unknown, and link operations paint nothing, so the map leaves them out (internal/web/debug_ops.go:24).

curl -s http://127.0.0.1:8122/debug/state

The route row is in documentation/web.md:32. It answers with Content-Type: application/json and Cache-Control: no-store (internal/web/debug_http.go:52).

Hot reload

Config.File reads the page source from disk at New and watches it. Config.ThemeFile does the same for the extra stylesheet (internal/page/page.go:46). The watch is on by default. Config.DisableHotReload or Page.SetHotReload(false) turns it off (internal/page/page_watch.go:53, internal/page/page_watch_api.go:13). Setting HTML and File together returns ErrBadSource, so there is no precedence rule (internal/page/page.go:20). Save an edit and the open window redraws within 250 ms (documentation/hot-reload.md:3).

The watch is a poll, not an OS notification. Every 250 ms the window calls PollReload on a screen that implements host.Reloader (internal/window/reload.go:12, documentation/hot-reload.md:26).

type Reloader interface {
    PollReload(ctx context.Context) (bool, error)
}

Two os.Stat calls a second on one file cost nothing (plans/v0.0.2/hot-reload.md:59). A Serve request adds one stat per watched path, and that is nothing next to a PNG encode (plans/v0.0.2/hot-reload.md:229). The call sits after tickFrame and before syncImage, so the generation sync picks up the new picture (internal/window/update.go:38). syncImage rebuilds the frame when the generation changed (internal/window/sync.go:43).

PollReload walks the two paths (internal/page/page_reload.go:12). pollSource stats the file first; the same modification time and size skips the read (internal/page/page_reload.go:64, internal/page/page_watch_api.go:26). A changed stat reads the bytes and compares a SHA-256 hash with the last accepted bytes. Only a different hash parses (internal/page/page_reload.go:79).

applySource swaps the template or the theme. A parse error keeps the last good one and stores the bytes as pending (internal/page/page_reload_apply.go:10). The next poll calls retryPending, which retries the same bytes even when the stat did not move, so a half-written save parses on a later poll (internal/page/page_reload_retry.go:7, documentation/hot-reload.md:44). A new edit that changes the file replaces the pending bytes (internal/page/page_reload_retry.go:17). A file that disappears keeps the last good picture and reports the stat error once per distinct message (internal/page/page_reload_state.go:6).

A successful swap sets the new template, replaces past[pastAt], clears pending, and redraws (internal/page/page_reload_apply.go:26, internal/page/page_reload.go:45). The history length and index do not move, so Back and Forward still walk older entries (internal/page/page_reload_apply.go:34).

The window prints each distinct error once and keeps drawing (internal/window/reload.go:48):

hot reload: <path>: <error>

A successful poll clears the line, so the same error after a fix prints again (internal/window/reload.go:38, documentation/hot-reload.md:55).

Serve has no frame loop. It calls the same poll before it answers GET / and GET /frame.png, under the same mutex, so the second request in a session sees an edit (internal/web/page_http.go:13, :47, internal/web/reload.go:18). While Watching() is true the shell page carries a small script that reloads the frame every 250 ms (internal/web/shell.go:22, internal/web/reload.go:36). A string page has no watch, so the shell emits no script (documentation/web.md:68).

The watch covers the template and the theme. It does not watch Go source, so a changed handler still needs a restart (documentation/hot-reload.md:88). wasm and mobile read Config.File once at New and never watch (documentation/hot-reload.md:91).
