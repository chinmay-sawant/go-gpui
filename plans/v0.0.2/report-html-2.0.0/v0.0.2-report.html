go-gpui v0.0.2: what shipped and how it works

One review file for the six v0.0.2 plans: the engine change, resize, repaint, devtools, hot reload, the Electron gaps, input, and how it was verified.

A drag and a click no longer reparse the page. The window lays out the cached document at the committed size, repaints only the changed box, and follows a file on disk. F12 opens an inspector, and forms gained a caret, focus traversal, selection, a context menu, touch scroll, and pinch. Every claim below cites a file that exists at commit 07c951c.

How v0.0.2 stopped Redraw from reparsing the page

v0.0.2 keeps the parsed HTML tree and the styled CSS document between redraws. A size or state change relayouts the cached document instead of reparsing the page.

v0.0.2 is six plans on one branch in the range 84cd317..07c951c (what shipped). Before the split, every Redraw ran html.Parse, css.Apply, and layout, so a window drag paid the full render per frame (the problem). internal/render.Cache holds the tree and the styled document, and a change calls css.Relayout (the split). The engine adds css.Relayout and a sheet cache on gowkhtmltopdf chore/changes-for-go-gpui (the engine change). host.Inspector counters show parses, cascades, layouts, and repaints in the devtools overlay and GET /debug/state; the plan files come next (counters, reading).

The problem

Before the split, every Redraw rebuilt the page from the template string. The stages ran in order: tpl.Execute, html.Parse, css.Apply, and layout.DisplayListOptions or layout.LayOptions (plans/v0.0.2/dynamic-resize.md:13-18). A drag emitted a size change per frame, so a drag paid a full page render per frame (plans/v0.0.2/dynamic-resize.md:17-18).

The stage benchmark split the cost (internal/page/page_bench_stages_test.go:14, plans/v0.0.2/dynamic-resize.md:87-94):

StageCost
template execute0.3 µs
html.Parse1.1 to 1.4 µs
css.Apply, 3 rules3 µs
css.Apply, 200 rules200 µs
layout.DisplayListOptions135 to 160 µs
layout.LayOptions3.6 to 4.7 ms

The numbers are orders of magnitude, because the machine was shared (plans/v0.0.2/dynamic-resize.md:83-85). The saving shows on a stylesheet-heavy page. BenchmarkRedrawHeavyWarm with 200 rules measured 1.34 to 1.83 ms before the split and 489 to 708 µs after (internal/page/page_bench_heavy_test.go:28-30, plans/v0.0.2/dynamic-resize.md:100-103). css.Relayout reuses the collected sheets in about 1.2 µs, where css.Apply costs about 200 µs and the parse costs more (plans/v0.0.2/dynamic-resize.md:101-103).

Redraw still executes the template on every call, because the executed bytes key the cache (internal/page/page_draw.go:25, internal/page/page_pipeline.go:20). The parse and the cascade are the stages the cache removes.

The test that pins the exit criterion

TestResizeReusesParseAndCascade calls SetSize and Redraw ten times with unchanged data (internal/page/page_cache_test.go:22-33). It asserts 1 parse, 1 cascade, 10 redraws, 10 layouts, and 10 repaints (internal/page/page_cache_test.go:35-45). That is the exit criterion of Phase 1 (plans/v0.0.2/dynamic-resize.md:105-106).

The split

internal/render.Cache holds three values: the executed source, the parsed *html.Document, and the styled *css.Document (internal/render/cache.go:16-20). NewCache parses the HTML and applies the sheets once (internal/render/cache.go:24-40). Cache.Relayout calls css.Relayout at a new viewport and pointer state, and stores the new styled document (internal/render/cache.go:55-67).

internal/render/document.go holds the layout half. DisplayListDocument and PaintDocument take the already styled document, so neither parses the HTML nor recollects the sheets (internal/render/document.go:15-26, :30-41).

internal/page/page_pipeline.go routes Redraw. styledDocument compares p.cache.Source() with the executed source (internal/page/page_pipeline.go:20). A match calls p.cache.Relayout(ctx, p.width, p.height, state) (internal/page/page_pipeline.go:21). A mismatch builds render.NewCache and counts one parse and one cascade (internal/page/page_pipeline.go:24-31).

// internal/page/page_pipeline.go:20
if p.cache != nil && p.cache.Source() == source {
    return p.cache.Relayout(ctx, p.width, p.height, state)
}

The cache drops when the source or the theme changes: SetData (internal/page/page_size.go:11), SetTheme (internal/page/theme.go:21), Load (internal/page/page_nav.go:36), and Back or Forward (internal/page/page_nav.go:86). SetSize does not drop it (internal/page/page_size.go:43-45), which is why a resize relayouts instead of reparsing. SetImage keeps it too, because the image resolver runs at layout (internal/page/page_set_image_cache_test.go:8-10).

render.State carries the focus, hover, and active ids into the cascade, so a state change takes the same relayout path (internal/render/state.go:8-18). State.options sets WidthPx and HeightPx, which is how media queries and viewport units see the new size (internal/render/state.go:21-31).

A hover keeps the cache and counts a second layout (internal/page/page_cache_test.go:48-68). A warm redraw never runs html.Parse or css.Apply again; a source or theme change does.

The engine change

The engine work lives in the sibling repo gowkhtmltopdf, branch chore/changes-for-go-gpui (PHASES.md:18). gowkhtmltopdf/css/relayout.go adds one entry point (gowkhtmltopdf/css/relayout.go:21-24):

func Relayout(
    ctx context.Context, doc *Document,
    width, height int, focus, hover, active string,
) (*Document, error)

The doc comment states the contract: Relayout shares doc's tree, which must not change, and reuses its parsed sheets and font registry (gowkhtmltopdf/css/relayout.go:10-16). Only the viewport-dependent collection gating for media links and media imports runs again (gowkhtmltopdf/css/relayout.go:13-15). The cascade itself still runs in layout, because @media rules, vw and vh lengths, and percentages resolve against the viewport stored here (gowkhtmltopdf/css/relayout.go:14-16).

The sheet cache is gowkhtmltopdf/internal/convert/prepare/sheet_cache.go. Keys are tree nodes or a parsed sheet plus an import index, so a cache belongs to exactly one tree (gowkhtmltopdf/internal/convert/prepare/sheet_cache.go:8-17). Relayout passes doc.cache to the collector (gowkhtmltopdf/css/relayout.go:60).

The parity gate is gowkhtmltopdf/layout/relayout_parity_test.go. TestRelayoutMatchesFullApply compares a relayout at 640x480 with a full Apply, box for box and op for op (gowkhtmltopdf/layout/relayout_parity_test.go:14-24). TestRelayoutDoesNotLeakBetweenSizes runs two relayouts in a row and compares the second with a fresh Apply, which catches a sheet cache or state leak (gowkhtmltopdf/layout/relayout_parity_test.go:27-39).

go-gpui consumes the branch through a replace: go.mod points the module at ../gowkhtmltopdf while the branch is unpushed (go.mod:46-48). The branch is ahead of its origin remote, and PHASES.md lists the push and the pin as the remaining integration work (PHASES.md:22-23).

Resize and repaint in go-gpui v0.0.2

A window drag now relayouts once per settled size, and a click now repaints one dirty rect instead of the whole page.

Dynamic resize: MaxWidth and MaxHeight bound the window, and a drag commits one relayout per settled size.
Incremental repaint: a declared or diffed dirty rect makes the window replay only the changed box.
The frame timeline: one diagram shows which frames redraw and which only copy the buffer.
Numbers: the platform counter repaints 5 of 11 operations and skips 6; one click costs about 0.5 ms.
The examples and what to read next.

Dynamic resize

MaxWidth and MaxHeight are window bounds, not layout caps. Page.MaxSize returns them (internal/page/page_size.go:31), and Clamp pulls a size up to the minimum only (internal/page/page_size.go:37). Run hands the pair to ebiten.SetWindowSizeLimits (internal/window/run.go:53, internal/window/run.go:56), so the OS stops the window at the bound. A screen without MaxSize stays unbounded (internal/window/bounds.go:13).

A drag records the outside size in Layout and marks the window as moving (internal/window/resize.go:49). The next update commits the size in resize (internal/window/resize.go:15). A size that held still for one update commits at once. A size that keeps changing relayouts at most every 100 ms, the value of relayoutEvery (internal/window/resize.go:10). Between commits the window draws the previous frame scaled to the window (internal/window/view.go:7, internal/window/draw.go:34).

A commit calls SetSize and Redraw (internal/window/resize.go:31, internal/window/resize.go:33). syncImage then rebuilds the drawn artifact (internal/window/resize.go:40), and built skips that rebuild when the generation and the size both match (internal/window/sync.go:43). The commit ends in refreshState, which re-resolves hover and press against the new boxes at the last cursor point (internal/window/resize.go:44, internal/window/resize_state.go:7). Update runs resize before pointer, so a hit test uses the boxes of the frame being drawn (internal/window/update.go:26, internal/window/update.go:30).

if moving && time.Since(s.lastRelayout) < relayoutEvery {
    s.skipped++
    return nil
}
s.app.SetSize(wantW, wantH)
if err := s.app.Redraw(s.ctx); err != nil {
    return err
}

A relayout does not parse or cascade. Redraw executes the template and calls styledDocument (internal/page/page_draw.go:34). When the executed source is unchanged, that call reuses the cached tree and runs Cache.Relayout for the new viewport and pointer state (internal/page/page_pipeline.go:20, internal/render/cache.go:53).

The scroll offset follows the new content. syncImage calls pullScroll after every rebuild (internal/window/sync.go:19), and pullScroll clamps the offset to the content size (internal/window/scroll_clamp.go:5).

Viewport units follow the window too. TestViewportUnitsFollowTheFrame lays out 50vw at 400 px and 20vh, 20dvh, 20svh, and 20lvh at 120 px in an 800x600 frame (internal/page/page_viewport_units_test.go:8). TestVarChainReadingAViewportUnitRecomputes checks a var() chain after SetSize(400, 600) (internal/page/page_viewport_units_test.go:31).

Engine gap: @media (height) never matches

The engine media-feature parser accepts only width and inline-size names, so (height), (min-height), and (max-height) never match. TestMediaHeightFollowsTheFrame is skipped with that reason (internal/page/page_viewport_test.go:31). The gap is recorded in plans/v0.0.2/dynamic-resize.md:176 and PHASES.md:29.

Incremental repaint

A click still ends in Redraw (internal/page/page_click.go:46), but the page now reports the changed region in CSS pixels through TakeDirty (internal/page/page_dirty.go:8). A handler can declare the id it changed with Page.Invalidate (internal/page/page_invalidate.go:10). When no handler declares, Redraw diffs the previous display list against the new one (internal/page/page_draw.go:43, internal/page/page_dirty.go:34).

a.view.Count++
a.page.SetData(a.view)
a.page.Invalidate("count")

Invalidate with an empty id, or with an id that has no box, marks the whole frame (internal/page/page_invalidate.go:11). A known id marks its box, the boxes inside it, and its previous rect for the same id (internal/page/page_invalidate.go:61). growBox unions every box inside the rect, so a nested span repaints with its parent (internal/page/page_dirty_box.go:14).

diffDisplay compares the lists operation by operation (internal/page/page_dirty_diff.go:15). It unions the bounds of every changed operation and the old bounds of every removed operation. It falls back to the frame when more than maxDirtyOps operations changed, which is 8, or when the union covers more than a third of the frame (internal/page/page_dirty_diff.go:11, internal/page/page_dirty_diff.go:59).

TakeDirty pads the rect by 4 px for shadows, outlines, and antialiasing (internal/page/page_dirty_box.go:7, internal/page/page_dirty.go:24), clamps it to the frame, and clears it. ok is false when nothing changed since the previous call (internal/page/page_dirty.go:20).

The window calls TakeDirty inside drawReplayPartial (internal/window/replay_partial.go:50). planRepaint picks one of four modes: repaint one rect, repaint the whole buffer, blit the buffer unchanged, or replay the list straight to the screen (internal/window/replay_plan.go:33). A rect mode fills the sub-image with the page background and calls replay.DrawRect into the persistent buffer (internal/window/replay_buffer.go:27, internal/window/replay_buffer.go:31). A blit copies the buffer to the screen without replaying an operation (internal/window/replay_partial.go:59).

DrawRect walks Display.Order the way Draw does and skips every op whose painted box does not meet the rect (internal/replay/draw_rect.go:16, internal/replay/draw_rect.go:32). A text op carries its baseline in Y, so the box test uses the line box, and an op whose ink cannot be bounded, such as a rotated run, is always drawn (internal/replay/draw_rect.go:56). The rect is clamped to the canvas first (internal/replay/draw_rect.go:50).

These paths still repaint the whole frame. SetTheme marks the frame (internal/page/theme.go:22), and so do Load and the drawAt call behind Back and Forward (internal/page/page_nav.go:37, internal/page/page_nav.go:87). A fallback bitmap page has no display list, so it keeps the full image path (internal/page/page_draw.go:68). A rect that clamps to the whole frame becomes a buffer rebuild (internal/window/replay_plan.go:48). A page with a frame callback keeps the full replay, because a tick edits operations in place and leaves no dirty rect (internal/window/replay_partial.go:44).

The frame timeline

One update runs resize, then pointer, then syncImage, and the draw that follows reads the result (internal/window/update.go:26, internal/window/update.go:46).

DevTools and hot reload

The window draws an inspector over the page, and it polls a file on disk for edits. Neither path changes the page picture.

DevTools: F12 or Ctrl+Shift+I opens an overlay with box outlines, operation colours, and frame stats.
The overlay is window chrome. It never calls Redraw, and a test holds the page PNG to the byte.
GET /debug/state serves the same numbers as JSON in web mode.
Hot reload polls Config.File and Config.ThemeFile every 250 ms. A bad parse keeps the last good picture.
The diagram traces one reload, and the table lists what the swap keeps and clears.

DevTools

Press F12 or Ctrl+Shift+I to toggle an overlay that the page owns. The window type-asserts host.Inspector on the screen it already holds (internal/window/devtools.go:40). A screen without the interface gets no overlay and no compile change (documentation/devtools.md:86).

type Inspector interface {
    DevTools() bool
    SetDevTools(on bool)
    Stats() Stats
}

Config.DevTools starts the overlay on (internal/page/page.go:54). Page.SetDevTools and Page.DevTools read and change the flag at runtime (internal/page/page_devtools.go:10). The window follows the flag once per frame in devSync (internal/window/devtools.go:48). A browser that keeps F12 for itself or a phone without a keyboard uses that switch (documentation/devtools.md:17).

The toggle keys belong to the window. devOwns claims F12, Ctrl+Shift+I, and o while the overlay is on (internal/window/devtools_own.go:6). devtoolsKeys runs before the page key handling, and devKeyStep swallows the press and the release (internal/window/devtools_keys.go:22). The page handler never sees either one (documentation/keys.md:56).

The overlay draws last. Draw fills the background, draws the content, then the scrollbars and the context menu, then drawDevTools when the flag is on (internal/window/draw.go:22).

Hovering outlines the innermost box under the cursor in red #e5484d. A click pins a box in blue #1a56db (internal/window/devtools_paint.go:14). Each outline has a label in the shape tag#id WxH (internal/window/devtools_paint.go:46). The panel sits at the bottom left, above the horizontal scrollbar strip, and sizes itself from the widest line (internal/window/devtools_panel_geom.go:5, internal/window/devtools_draw.go:33).

Ops mode outlines every operation in paint order. drawDevOps walks display.Order and colours each outline by kind (internal/window/devtools_ops.go:23). Fills are blue, strokes red, lines orange #d97706, text green #176b45, images violet #7c3aed, grid runs cyan #0891b2 (internal/window/devtools_ops.go:12). Noop and unknown operations paint nothing and get no outline. A text operation carries its baseline in Y, so the outline uses the line box from op.InkDescent - op.H (internal/window/devtools_counts.go:67).

The stats panel prints ten lines, plus one for a hovered box and one for a pinned box (internal/window/devtools_stats.go:26).

The overlay never touches the page

The overlay is window chrome, the way the scrollbar thumbs and the fallback badge are (documentation/devtools.md:3). No path in internal/window calls Redraw to show it, and drawDevTools only reads shell state (internal/window/devtools_draw.go:15).

TestDevToolsLeavesPageAlone renders one page with the overlay off and on and compares the results (internal/window/devtools_page_test.go:16). A click pins the box under the cursor. A click on the same box or anywhere on the panel clears the pin (internal/window/devtools_pick.go:57, :42). Alt+click forwards Press and Click to the page, and the release follows the forwarded press (internal/window/devtools_pick.go:57, :31).

GET /debug/state

Hot reload

Config.File reads the page source from disk at New and watches it. Config.ThemeFile does the same for the extra stylesheet (internal/page/page.go:46). The watch is on by default. Config.DisableHotReload or Page.SetHotReload(false) turns it off (internal/page/page_watch.go:53, internal/page/page_watch_api.go:13). Setting HTML and File together returns ErrBadSource, so there is no precedence rule (internal/page/page.go:20). Save an edit and the open window redraws within 250 ms (documentation/hot-reload.md:3).

The watch is a poll, not an OS notification. Every 250 ms the window calls PollReload on a screen that implements host.Reloader (internal/window/reload.go:12, documentation/hot-reload.md:26).

type Reloader interface {
    PollReload(ctx context.Context) (bool, error)
}

Two os.Stat calls a second on one file cost nothing (plans/v0.0.2/hot-reload.md:59). A Serve request adds one stat per watched path, and that is nothing next to a PNG encode (plans/v0.0.2/hot-reload.md:229). The call sits after tickFrame and before syncImage, so the generation sync picks up the new picture (internal/window/update.go:38). syncImage rebuilds the frame when the generation changed (internal/window/sync.go:43).

PollReload walks the two paths (internal/page/page_reload.go:12). pollSource stats the file first; the same modification time and size skips the read (internal/page/page_reload.go:64, internal/page/page_watch_api.go:26). A changed stat reads the bytes and compares a SHA-256 hash with the last accepted bytes. Only a different hash parses (internal/page/page_reload.go:79).

applySource swaps the template or the theme. A parse error keeps the last good one and stores the bytes as pending (internal/page/page_reload_apply.go:10). The next poll calls retryPending, which retries the same bytes even when the stat did not move, so a half-written save parses on a later poll (internal/page/page_reload_retry.go:7, documentation/hot-reload.md:44). A new edit that changes the file replaces the pending bytes (internal/page/page_reload_retry.go:17). A file that disappears keeps the last good picture and reports the stat error once per distinct message (internal/page/page_reload_state.go:6).

A successful swap sets the new template, replaces past[pastAt], clears pending, and redraws (internal/page/page_reload_apply.go:26, internal/page/page_reload.go:45). The history length and index do not move, so Back and Forward still walk older entries (internal/page/page_reload_apply.go:34).

The window prints each distinct error once and keeps drawing (internal/window/reload.go:48):

hot reload: <path>: <error>

A successful poll clears the line, so the same error after a fix prints again (internal/window/reload.go:38, documentation/hot-reload.md:55).

Serve has no frame loop. It calls the same poll before it answers GET / and GET /frame.png, under the same mutex, so the second request in a session sees an edit (internal/web/page_http.go:13, :47, internal/web/reload.go:18). While Watching() is true the shell page carries a small script that reloads the frame every 250 ms (internal/web/shell.go:22, internal/web/reload.go:36). A string page has no watch, so the shell emits no script (documentation/web.md:68).

The watch covers the template and the theme. It does not watch Go source, so a changed handler still needs a restart (documentation/hot-reload.md:88). wasm and mobile read Config.File once at New and never watch (documentation/hot-reload.md:91).

Drag and drop

The window reads ebiten.DroppedFiles() once per frame, after the pointer pass (internal/window/update.go:34). The call returns an fs.FS scoped to that frame. A nil file system means no drop, and a screen without the drop method ignores the files (internal/window/drop.go:13, :26).

shell.dropPass reads the root entries and builds one host.Drop per entry (internal/window/drop.go:36). Each value carries a name, a size, a directory flag, an absolute path on desktop, and a Read function (internal/host/drop.go:8). A dropped directory stays one entry with IsDir true; the window never walks the tree (internal/window/drop.go:34).

Read calls fs.ReadFile through the frame file system, so it serves bytes only during the call (internal/window/drop.go:69). The path comes from the entry's AbsPath method, which desktop entries have (internal/window/drop.go:74).

The page handler

Page.Drop calls Handlers.Drop and then draws the page again. An error returns before the redraw (internal/page/page_drop.go:14, internal/page/page_drop.go:25). The handler field takes the same slice (internal/page/page_handlers.go:43), and gpui.Drop is the root name for the type (drop.go:6).

Frame scope

A handler that reads the bytes and stores them keeps them (documentation/drag-drop.md:53). A saved Read is not valid after the call, and a handler that returns without reading gets nothing (documentation/drag-drop.md:54).

Web and wasm

-web runs the page through internal/web, not the Ebiten loop. It never reads ebiten.DroppedFiles, and no route carries a drop (documentation/drag-drop.md:61). The wasm canvas build runs the same Update as the desktop window, so a browser drop arrives there (documentation/drag-drop.md:62).

Input and interaction in go-gpui v0.0.2

v0.0.2 gives a form a caret, a selection range, Tab focus, pointer gestures, and touch scrolling; in v0.0.1 a click only focused a field and typing only appended to the value.

The form keeps a caret and an anchor, so typing inserts at the click and an insert replaces a selection (caret and range).
Click-to-glyph measures the shaped text run through internal/textrun, and an unmeasurable run falls back to the end of the value (click to glyph).
Tab moves focus in document order, the arrows and Home and End move the caret, and Shift extends the range (keyboard).
A drag selects, double and triple click select a word and a line, a right click opens a menu, and the cursor follows the hovered element (pointer).
Page.ScrollTo and ScrollBy queue a request, touch drags and pinches, and F11 toggles fullscreen; the scroll section, event map, change table, and reading list follow.

The caret and the selection range

formState carries the caret and the anchor as rune offsets into the focused value (internal/page/form_types.go:39). The two offsets normalize to [start, end), and the caret stays at the moving end (internal/page/form_range.go:11).

Typing inserts at the caret and replaces a non-empty selection (internal/page/form_edit_value.go:4). Backspace and DeleteWord use the same range. Each removes the selection, or the rune or the word before the caret (internal/page/form_edit_value.go:22, internal/page/form_edit_value.go:37).

SelectAll sets the range to [0, len) (internal/page/page_edit.go:32). A blur clears the range, and a click in a different control drops it and places a new caret (internal/page/form_range.go:42, internal/page/form_input.go:51).

// internal/page/form_edit_value.go:10
start, end := rangeOf(anchor, caret, len(runes))
out := make([]rune, 0, len(runes)-(end-start)+len(ins))
out = append(out, runes[:start]...)
out = append(out, ins...)
out = append(out, runes[end:]...)

A redraw keeps the values and then clamps the caret and the anchor to the new value length, so a redraw does not move a surviving caret (internal/page/form_apply.go:30, internal/page/form_range.go:52).

A caret-only move calls setCaret and Redraw (internal/page/form_caret_keys.go:60). It does not call applyEdit, so it fires no BeforeEdit and no Change (internal/page/form_key.go:43).

How the range survives a redraw

mergeControls keeps the user's value for each text control across a parse (internal/page/form_merge.go:5). syncForm calls clampRange after the merge (internal/page/form_apply.go:30). A focus that vanished in the new document clears the caret and the anchor (internal/page/form_range.go:53). The same path runs on a hot reload, so a caret in a watched template survives the swap.

The control rewrite paints the caret as a split in the field span and wraps the selected runes in data-gpui-selection (internal/page/form_html_caret.go:61).

Click to glyph

A press in a field calls SelectAt (internal/page/form_select.go:9). SelectAt focuses the control under the point and asks offsetAt for the rune offset (internal/page/form_select.go:34, internal/page/form_offset.go:13).

offsetAt calls textrun.At, which walks the text operations in the page display list and lines them up with the shown value (internal/textrun/textrun.go:24). It picks the line nearest the y point and the rune nearest the x point inside that line (internal/textrun/lines.go:56, internal/textrun/run.go:60).

A run that cannot be measured, or one whose drawn text does not line up with the value, lands at the end of the value (internal/page/form_offset.go:16). The recorded fallback shapes are a page with no display list, a run whose drawn text does not line up with the value, and a font that cannot be parsed (plans/v0.0.2/input-interaction.md:306).

The window calls SelectAt from pressAt, after Press and Click (internal/window/drag_select.go:19). The -web click route calls Click and then SelectAt (internal/web/input_http.go:33).

Keyboard focus and caret keys

Tab and Shift+Tab move focus when the screen implements host.Focuser (internal/window/focus_keys.go:37). The window calls FocusNext or FocusPrev, reads FocusID, and consumes the press and its release when a field took the focus (internal/window/focus_keys.go:43, internal/window/focus_keys.go:57).

The page builds the order from the control boxes in document order and skips disabled controls and tabindex="-1" (internal/page/form_focus_order.go:5). The step wraps at both ends (internal/page/form_focus.go:88). Escape closes the context menu first, then clears focus with Focus(ctx, "") (internal/window/focus_keys.go:63).

With a text field focused, KeyDown runs the handler and then caretKey (internal/page/page_key.go:8). Arrow Left and Right move by rune, and Home and End move to the ends (internal/page/form_caret_keys.go:23). A ctrl+ or alt+ prefix jumps by word, and a shift+ prefix extends the range from the anchor (internal/page/form_caret_keys.go:66).

// internal/window/key_event_name.go:20
if mods.Shift {
    name = "shift+" + name
}
if mods.command() {
    name = "ctrl+" + name
} else if mods.Alt {
    name = "alt+" + name
}

The window adds those prefixes to the four caret key names before the page sees them (internal/window/key_event_name.go:8).

What still reaches the key handler

Arrow keys, Home, End, and Escape still reach Handlers.KeyDown (documentation/keys.md:52). Tab does not reach it when a field took the focus, because the window consumes the press and the release (documentation/keys.md:46). A page without fields keeps Tab, because the window only consumes the key when FocusID is non-empty (internal/window/focus_keys.go:53).

One recorded limit: Up and Down in a textarea do nothing, because the value model is a single line (PHASES.md:32).

Pointer drag, menu, and cursor

pressAt records the press point and sets dragActive; each move with the button down calls Drag on the page (internal/window/drag_select.go:19, internal/window/drag_select.go:53). The page moves the far end of the range and redraws (internal/page/form_select.go:39).

Two rapid presses at one spot call SelectWordAt, and a third calls SelectLineAt. The gap is 400 ms and the spot may move 4 px (internal/window/click_watch.go:9, internal/window/click_watch.go:10, internal/window/drag_select.go:40). A drag past the top or bottom edge scrolls one wheel step per frame with the wheel clamp (internal/window/drag_scroll.go:19).

A right click asks the page for rows through ContextMenu and draws them at the cursor (internal/window/context_menu.go:19, internal/page/page_menu.go:8). The rows are cut, copy, paste, select all, undo, and redo. The page enables each row from its state: cut and copy need a selection, paste needs a focused editable field, and undo and redo need their handler (internal/page/page_menu.go:12).

menuAction routes a row to Cut, Copy, Paste, SelectAll, Undo, or Redo (internal/window/menu_action.go:68). Paste reads the clipboard and strips carriage returns and newlines (internal/window/menu_action.go:75). A left click on a row runs the action and closes the menu; a left click elsewhere or Escape closes it; a new right click reopens it at the new point (internal/window/context_menu.go:57, documentation/interaction.md:21).

applyCursor reads CursorShape after each hover and sets the Ebiten cursor only when the shape changed (internal/window/cursor.go:40, internal/page/page_cursor.go:8). A text control maps to the I-beam, a link or button to the hand, and a scrollbar thumb to the matching resize cursor (internal/window/cursor.go:12, internal/window/cursor.go:51). wasm and mobile ignore the call and keep their own cursor (internal/window/cursor.go:29).

Scrolling, touch, and fullscreen

Page.ScrollTo queues an absolute target, and Page.ScrollBy queues a delta (internal/page/page_scroll.go:7, internal/page/page_scroll.go:15). The window consumes the request through TakeScroll, clamps it to the content size, and clears it (internal/window/scroll_request.go:10, internal/page/page_scroll.go:22).

A touch that moves past 8 px drags the page. The content follows the finger and stops at the content ends (internal/window/touch_gesture.go:6, internal/window/touch_gesture.go:41, internal/window/pointer_touch.go:20). A still touch that lifts sends press, click, and release as a tap (internal/window/pointer_touch.go:27).

Two fingers pinch a zoom. pinchScale multiplies the base zoom by the change in finger span and clamps the result between 0.25 and 4 (internal/window/pinch.go:12, internal/window/pinch.go:6). contentPointZoom divides the zoom out of a click, so a click under a pinch lands on the same box (internal/window/zoom.go:19).

F11 toggles ebiten.SetFullscreen on desktop, and the window consumes the press and its release (internal/window/fullscreen.go:48). wasm and mobile keep their own fullscreen (internal/window/fullscreen.go:11).

Out of scope by design

Eleven items stay out of v0.0.2. Each one carries a recorded reason, so nobody reads an absence list and assumes the release covers it (plans/v0.0.2/electron-gaps.md:9).

ItemWhy it stays out
IME compositionThe window must wire Ebiten exp/textinput and the page must draw the composing run; both are next-cycle work (PHASES.md:28, plans/v0.0.2/electron-gaps.md:177).
CanvasThe engine ignores <canvas> and gives no drawing surface, and there is no JavaScript engine (plans/v0.0.2/electron-gaps.md:166).
AccessibilityThe window is one canvas with no accessibility tree and no platform bridge (plans/v0.0.2/electron-gaps.md:194).
VideoThe standard library has no demuxer or decoder, and a codec module breaks the no-new-modules rule (plans/v0.0.2/electron-gaps.md:207).
WebGLEbiten owns the graphics context and exposes no GL calls (plans/v0.0.2/electron-gaps.md:216).
Auto-updateA library cannot replace its own host binary portably, and the OS stores own the install (plans/v0.0.2/electron-gaps.md:222).
-web file drops-web has no window loop, so it receives no drops; the wasm canvas does (PHASES.md:14, plans/v0.0.2/electron-gaps.md:79).
Partial bitmap repaintThe engine paints the whole canvas, so a partial path needs a new imageout call (PHASES.md:30, plans/v0.0.2/incremental-repaint.md:149).
@media (height) in the engineThe media parser accepts only width and inline-size names, so the height branch never matches (PHASES.md:29, plans/v0.0.2/dynamic-resize.md:176).
Computed styles in the inspectorThe engine styles a document internally and publishes no per-element reader (PHASES.md:34, plans/v0.0.2/devtools.md:249).
Up/Down in a textareaThe value model is a single line (PHASES.md:32, plans/v0.0.2/input-interaction.md:294).
