Electron gaps closed in v0.0.2

v0.0.2 closes three Electron gaps: drag and drop, printing, and packaging.

Three gaps close in v0.0.2. Drag and drop reads the dropped files of one frame and calls the page handler. Printing renders the template to PDF and hands it to the OS print path. Packaging writes one release archive per system, with a dry run. The gap list records what stays out, including the corrected IME record. The summary table names the example and the entry point for each item.

The gap list

The plan records ten Electron features in one table (plans/v0.0.2/electron-gaps.md:16). Four land in v0.0.2: DevTools under its own plan, plus drag and drop, printing, and packaging (plans/v0.0.2/electron-gaps.md:9). This page covers the last three. The v0.0.1 framing still holds: there is no Chromium, no V8, and no second process (plans/v0.0.2/electron-gaps.md:12).

The corrected IME record

Commit f67fe66 corrected the IME row. The earlier record said Ebiten had no preedit API, so IME was blocked upstream. Ebiten v2.10.4 ships the experimental exp/textinput package (plans/v0.0.2/electron-gaps.md:183). Composer.OnComposition carries the composing text, SessionOptions.CaretBounds carries the caret rectangle, and OnCommit and OnEnd carry the lifecycle. The remaining work is window wiring plus a page-side composing run, not an upstream ask (PHASES.md:28).

Drag and drop

The window reads ebiten.DroppedFiles() once per frame, after the pointer pass (internal/window/update.go:34). The call returns an fs.FS scoped to that frame. A nil file system means no drop, and a screen without the drop method ignores the files (internal/window/drop.go:13, :26).

shell.dropPass reads the root entries and builds one host.Drop per entry (internal/window/drop.go:36). Each value carries a name, a size, a directory flag, an absolute path on desktop, and a Read function (internal/host/drop.go:8). A dropped directory stays one entry with IsDir true; the window never walks the tree (internal/window/drop.go:34).

Read calls fs.ReadFile through the frame file system, so it serves bytes only during the call (internal/window/drop.go:69). The path comes from the entry's AbsPath method, which desktop entries have (internal/window/drop.go:74).

The page handler

Page.Drop calls Handlers.Drop and then draws the page again. An error returns before the redraw (internal/page/page_drop.go:14, internal/page/page_drop.go:25). The handler field takes the same slice (internal/page/page_handlers.go:43), and ownframe.Drop is the root name for the type (drop.go:6).

Frame scope

The frame scope is the honest limit (documentation/drag-drop.md:48). A handler that keeps the path can open the file later on desktop (documentation/drag-drop.md:52). A handler that reads the bytes and stores them keeps them (documentation/drag-drop.md:53). A saved Read is not valid after the call, and a handler that returns without reading gets nothing (documentation/drag-drop.md:54).

Web and wasm

-web runs the page through internal/web, not the Ebiten loop. It never reads ebiten.DroppedFiles, and no route carries a drop (documentation/drag-drop.md:61). The wasm canvas build runs the same Update as the desktop window, so a browser drop arrives there (documentation/drag-drop.md:62).

examples/drop listens on 127.0.0.1:8124 with -web (examples/drop/main.go:18). The example registers Drop: app.onDrop on the page (examples/drop/drop/drop_new.go:18). A dropped PNG or JPEG shows through SetImage (examples/drop/drop/drop_handler.go:42), a dropped .txt shows its first lines (examples/drop/drop/drop_handler.go:52), and a directory shows one status line (examples/drop/drop/drop_handler.go:28).

Printing

Page.PDF returns the PDF bytes (internal/page/print.go:30). Page.WritePDF writes them to an io.Writer (internal/page/print.go:40), and Page.SavePDF writes them to a file and removes the file when the write fails (internal/page/print.go:50, internal/page/print.go:60). ownframe.SavePDF is the package form for a caller that holds the page separately (internal/page/print_doc.go:11).

Page.Print writes a temporary PDF and hands it to the OS print path (internal/page/print_os.go:16). A failed hand-off removes the temporary file. A successful hand-off leaves it for the system temp cleaner, because a viewer can read it after the call returns (internal/page/print_os.go:29).

The render source

The render starts from the last executed template output, p.source, which is the same string the next Redraw would execute (internal/page/print_doc.go:49). When nothing has drawn yet, pdfSource executes the template first (internal/page/print_doc.go:51). The current theme goes into a style element before </head> (internal/page/print_doc.go:64). PDFOptions carries a page size, one margin in millimetres, and a profile; the zero value is A4, 10 mm margins, and no profile (internal/page/print.go:13, documentation/printing.md:19).

internal/print tries the helpers for the system in order, and Available is true only on Linux, Windows, and macOS (internal/print/print.go:21).

OWNFRAME_PRINT_DEBUG=1 logs each lookup, the command that ran, and each fallback to stderr (internal/print/print.go:70).

Web mode

Serve registers GET /pdf when the screen implements PDF (internal/web/server.go:52). The route returns the bytes with Content-Type: application/pdf and Cache-Control: no-store (internal/web/pdf_http.go:30). examples/print serves it on 127.0.0.1:8125 (examples/print/main.go:18), with one button for Save PDF and one for Print (examples/print/print/report_click.go:13).

The PDF is a re-render from source, so pagination can differ from the window, and the display list is not printed (documentation/printing.md:67). An image registered with SetImage does not appear, because the source goes to the engine as in-memory HTML (documentation/printing.md:73).

Packaging

scripts/package.sh <example> builds one example for this system and writes a release archive to dist/ (documentation/packaging.md:3). The build uses -trimpath and -ldflags "-s -w" (scripts/package.sh:98). The script makes no network calls and adds no modules.

SHA256SUMS sits next to the archives and covers the archives from the same run (scripts/package.sh:178). The wasm zip uses the repository's browser/index.html, so serve the unpacked directory over HTTP (documentation/packaging.md:52).

The dry run

scripts/package.sh -n <example> prints the archive names and every entry and builds nothing (scripts/package.sh:83). The dry run still asks Go for GOOS and GOARCH, so GOOS=darwin sh scripts/package.sh -n print prints the macOS layout on any system (documentation/packaging.md:14). scripts/package_test.sh checks that output against the documented layouts and needs no build (scripts/package_test.sh:21).

Signing, notarization, and auto-update

The script ships unsigned archives (documentation/packaging.md:62). Linux has no signing step. macOS Gatekeeper blocks an unsigned .app on first launch; the person can right-click and choose Open, or you sign and notarize outside the script with codesign, notarytool, and stapler (documentation/packaging.md:65). Windows SmartScreen warns on an unsigned .exe; an Authenticode certificate and signtool remove the warning (documentation/packaging.md:70). Auto-update is not included and not planned, because a library cannot replace its own host binary; a product builds its own cmd/updater (documentation/packaging.md:81).
